## Задание 1. Стратегия сопровождения для управления модификацией и перемещением программных продуктов согласно стратегии выпусков

### 1.1. Исходная ситуация и цель

Система BMC_analyzer создана в 2000-е годы и обслуживалась по незашифрованному протоколу HTTP. Исходный код собирался на виртуальной машине Linux, которая к моменту выполнения задания уже не функционирует. Руководство Компании 1 инициировало запрос MR-2026-001 — переход с HTTP на HTTPS на всех сайтах.

**Тип сопровождения по ГОСТ 12207:**
- **Адаптивное** (Adaptive Maintenance) — адаптация к новым требованиям среды безопасности без изменения функциональности;
- **Профилактическое** (Perfective Maintenance) — контейнеризация, обновление компонент согласно актуальным версиям вендоров.

## Задание 2. Изменения в существующей системе: архитектура, операции, интерфейсы

### 2.1. Изменения в архитектуре

**До модификации (v1.x — HTTP):**
```
Браузер → HTTP:80 → Django runserver (Linux VM, EOL)
— нет шифрования
— нет HSTS, нет CSP, нет заголовков безопасности
— нет контейнеризации
— сборка на виртуальной машине 2000-х годов (уже не работает)
```

**После модификации (v2.0.0 — HTTPS):**
```
Браузер → HTTPS:443 → TLS-прокси (Nginx / Replit Proxy) → Django:3000 (Docker-контейнер)
— TLS 1.3 (RFC 8446)
— HSTS max-age=31 536 000; includeSubDomains; preload
— CSP, X-Frame-Options, X-Content-Type-Options, X-XSS-Protection и др.
— HttpsRedirectMiddleware: редирект HTTP → HTTPS (301)
— Docker-контейнер python:3.10-slim устраняет зависимость от EOL VM
```

### 2.2. Изменения в операциях (новые и изменённые компоненты)

| Компонент | Изменение | Файл |
|-----------|-----------|------|
| `HttpsRedirectMiddleware` | **Создан** — перехватывает HTTP (X-Forwarded-Proto: http), выполняет редирект 301 на HTTPS | `bmc_analyzer/middleware.py` |
| `SecurityHeadersMiddleware` | **Создан** — добавляет 7 заголовков безопасности ко всем ответам | `bmc_analyzer/middleware.py` |
| `settings.py` | **Обновлён** — SECURE_*, SESSION_COOKIE_SECURE, CSRF_COOKIE_SECURE, HSTS, CSRF_TRUSTED_ORIGINS | `django_project/settings.py` |
| `views.py` | **Обновлён** — добавлены обработчики `docs()` и `security_status()` | `bmc_analyzer/views.py` |
| `urls.py` | **Обновлён** — добавлены маршруты `/docs/` и `/api/security-status/` | `bmc_analyzer/urls.py` |
| `Dockerfile` | **Создан** — контейнер python:3.10-slim, HEALTHCHECK, Gunicorn | `Dockerfile` |
| `requirements.txt` | **Создан** — зафиксированы Python-зависимости | `requirements.txt` |

**Установленные заголовки безопасности (SecurityHeadersMiddleware):**
1. `Strict-Transport-Security: max-age=31536000; includeSubDomains; preload`
2. `X-Content-Type-Options: nosniff`
3. `X-Frame-Options: SAMEORIGIN`
4. `X-XSS-Protection: 1; mode=block`
5. `Referrer-Policy: strict-origin-when-cross-origin`
6. `Permissions-Policy: geolocation=(), microphone=(), camera=()`
7. `Content-Security-Policy: default-src 'self' https: ...`

### 2.3. Изменения в интерфейсах

| Интерфейс | До (v1.x) | После (v2.0.0) |
|-----------|-----------|---------------|
| URL-схема | `http://` | `https://`; при HTTP — редирект 301 |
| Порт | 80 (HTTP) | 443 (HTTPS) + редирект 80→443 |
| Cookie сессии | Secure=False, HttpOnly=False | Secure=True, HttpOnly=True, SameSite=Lax |

## Задание 4. Разработка модифицированного программного продукта (контейнер) в SaaS Replit

### 4.1. Обоснование перехода к контейнеризации

Исходная виртуальная машина Linux (2000-е годы) более не функционирует, что делает невозможным воспроизведение первоначальной среды сборки. Для обеспечения воспроизводимости и независимости от физического хоста приложение упаковано в Docker-контейнер.

### 4.2. Dockerfile (контейнер v2.0.0)

```dockerfile
FROM python:3.10-slim

LABEL maintainer="company2-dev@example.com"
LABEL version="2.0.0"
LABEL description="BMC_analyzer — HTTP→HTTPS (MR-2026-001, ГОСТ 12207)"

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    DJANGO_SETTINGS_MODULE=django_project.settings \
    DEBUG=False

WORKDIR /app

RUN apt-get update && apt-get install -y --no-install-recommends \
        gcc curl \
    && rm -rf /var/lib/apt/lists/*

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

RUN python manage.py collectstatic --noinput 2>/dev/null || true

EXPOSE 3000

HEALTHCHECK --interval=30s --timeout=10s --start-period=15s --retries=3 \
    CMD curl -f http://localhost:3000/login/ || exit 1

CMD ["python", "manage.py", "runserver", "0.0.0.0:3000"]
```

### 4.3. Развёртывание в SaaS Replit

В среде Replit TLS-терминация выполняется автоматически платформенным прокси. Django-приложение работает на порту 3000 и принимает запросы с заголовком `X-Forwarded-Proto: https`. Middleware `HttpsRedirectMiddleware` анализирует этот заголовок и при необходимости выполняет редирект 301.

### 4.4. API проверки безопасности

Эндпоинт `GET /api/security-status/` (требует авторизации):

```json
{
  "protocol": "HTTPS",
  "is_secure": true,
  "version": "2.0.0",
  "hsts_enabled": true,
  "security_headers": [
    "Strict-Transport-Security",
    "X-Content-Type-Options",
    "X-Frame-Options",
    "X-XSS-Protection",
    "Referrer-Policy",
    "Permissions-Policy",
    "Content-Security-Policy"
  ]
}
```

## Задание 5. Тесты по ГОСТ Р 56920 и IEEE 829

### 5.1. Спецификация процедуры тестирования (А.В.0001-05-СП)

**Область применения.** Настоящая спецификация определяет последовательность действий для выполнения тестов, описанных в А.В.0001-05-ТС. Процедуры предназначены для автоматизированного и ручного выполнения в рамках подпроцессов модульного, функционального, приёмочного тестирования и тестирования безопасности (ГОСТ Р 56920, §7.3–7.6).

**Процедура автоматизированного тестирования:**
1. Открыть терминал в корне проекта.
2. Выполнить команду: `pytest bmc_analyzer/tests.py -v --tb=short`
3. Наблюдать вывод: количество пройденных/упавших тестов.
4. При наличии упавших тестов зафиксировать: ID теста, ожидаемое и фактическое значения, сообщение об ошибке.
5. Записать результаты в протокол испытаний.

*Критерий завершения: 100% тестов пройдено.*

**Процедура ручного функционального тестирования:**
1. Запустить сервер: `python manage.py runserver 0.0.0.0:3000`
2. В браузере ввести `http://...` — убедиться в автоматическом редиректе на `https://...`
3. Убедиться в наличии иконки замка в адресной строке
4. Войти под учётной записью admin, просмотреть таблицы и графики
5. В инструментах разработчика (вкладка Network) проверить заголовок `Strict-Transport-Security`
6. Проверить цветовую индикацию гистограммы (зелёный/жёлтый/красный)
7. Через `/admin/` изменить параметры команды, обновить страницу, проверить пересчёт
