1. Спецификация процедуры тестирования (А.В.0001-05-СП)
1.Область применения
Настоящая спецификация определяет последовательность действий (процедуры) для выполнения тестов, описанных в спецификации тестов (А.В.0001-05-ТС). Процедуры предназначены для ручного и автоматизированного выполнения в рамках подпроцессов модульного, функционального и приёмочного тестирования контейнера безопасности «BMC_analyzer».
2.Процедура автоматизированного модульного тестирования
Цель: проверить корректность функций расчёта индекса угрозы (calculate_risks) и генерации графиков.
Предварительные условия: установлены Python, Django, pytest, pytest-django; проект развёрнут.
Шаги:
1. Открыть терминал (Shell) в корне проекта.
2. Выполнить команду pytest -v --tb=short.
3. Наблюдать вывод: количество пройденных/упавших тестов.
4. Если есть упавшие тесты, зафиксировать:
 идентификатор теста (например, test_normal_case);
 ожидаемое и фактическое значения;
 сообщение об ошибке.
5. Записать результаты в протокол испытаний.
Критерий завершения: все тесты выполнены, процент прохождения 100% (допускаются пропуски только по согласованию).
3. Процедура ручного функционального тестирования (сценарий)
Цель: проверить аутентификацию, расчёт индекса, отображение таблиц и графиков, администрирование.
Предварительные условия: сервер запущен (python manage.py runserver), база данных содержит начальные команды (8 шт.), создана учётная запись admin, браузер открыт.
Шаги:
3.1. Проверка аутентификации
1.	В адресной строке ввести URL сервера. Ожидается: редирект на /login/.
2.	Ввести неверный пароль (логин admin, пароль wrong), нажать «Войти». Ожидается: сообщение о необходимости ввести корректные данные.
3.	Ввести верные данные (admin ), нажать «Войти». Ожидается: редирект на / и отображение главной страницы.
4.	Нажать кнопку «Выйти». Ожидается: редирект на /login/.
3.2. Проверка расчёта индекса
1.	Войти как администратор.
2.	Перейти в админ-панель (/admin/), в разделе Command policies выбрать команду «монтировать ISO», установить частоту = 2, критичность = 0,9, сохранить.
3.	Вернуться на главную страницу, открыть вкладку «Исходный индекс угрозы». Ожидается: в строке «монтировать ISO» значение индекса = 1,8.
4.	Перейти на вкладку «Усиленный индекс угрозы». Ожидается: критичность = 1,08, индекс = 2,16.
3.3. Проверка отображения таблиц и графиков
1.	На вкладке «Исходный индекс угрозы» убедиться в наличии колонок: №, Команда, Частота, Критичность, Индекс угрозы (R).
2.	Убедиться, что столбчатая диаграмма содержит столбцы с цветами: зелёный (≤1), жёлтый (1–2), красный (>2).
3.	Убедиться, что круговая диаграмма отображает проценты и номера команд (или названия при наведении).
4.	Перейти на вкладку «Графики сравнения». Ожидается: линейный график с двумя линиями (синяя – исходный, оранжевая – усиленный) и подписанными осями.
3.4. Проверка администрирования
1.	В админ-панели изменить для команды «монтировать ISO» частоту на 3, критичность на 0,95, сохранить.
2.	Обновить главную страницу. Ожидается: в таблице «Исходный индекс» частота = 3, критичность = 0,95, индекс = 2,85.
3.	Убедиться, что столбец на диаграмме стал красным (риск >2).
Критерий завершения: все шаги выполнены, фактические результаты совпадают с ожидаемыми. При первом несовпадении тестирование останавливается, дефект регистрируется.

1. Реализация примера автоматизированного модульного тестирования на базе фреймворков
Описание алгоритма действий
1. Установить pytest. Для этого в терминале (Shell) Replit выполнить:
pip install pytest pytest-django
2. Создать в корне проекта файл pytest.ini со следующим кодом:
[pytest]
DJANGO_SETTINGS_MODULE = django_project.settings
python_files = tests.py
3. Написать код для модульных тестов и вставить его в файл bmc_analyzer/tests.p.
4. Запустить тесты. Для этого в терминале выполнить команду:
pytest -v

2. Реализация примера ручного приёмочного тестирования
1. Открыть веб-браузер и перейти по адресу приложения.
2. Убедиться, что происходит перенаправление на страницу /login/.
3. Ввести заведомо неверный пароль (логин admin, пароль wrong) и нажать «Войти». Убедиться, что отображается сообщение об ошибке.
4. Ввести верные учётные данные (admin) и нажать «Войти». Убедиться, что выполнен переход на главную страницу / и отображаются таблицы с графиками.
5. На вкладке «Исходный индекс угрозы» найти команду «монтировать ISO» (частота = 2, критичность = 0,9). Проверить, что индекс угрозы равен 1,8.
6. Убедиться, что столбчатая диаграмма для этой команды имеет жёлтый цвет (значение индекса в интервале 1–2).
7. Перейти на вкладку «Усиленный индекс угрозы». Проверить, что критичность команды «монтировать ISO» стала 1,08, а индекс – 2,16.
8. Перейти на вкладку «Графики сравнения». Убедиться, что отображается линейный график с двумя линиями: синей (исходный индекс) и оранжевой (усиленный индекс).
9. Нажать ссылку «Админ-панель» (доступна только администратору). В разделе Command policies выбрать команду «монтировать ISO», изменить частоту на 3, критичность на 0,95 и сохранить изменения.
10. Вернуться на главную страницу и обновить её. Проверить, что в таблице «Исходный индекс угрозы» для команды «монтировать ISO» отображаются новые значения: частота = 3, критичность = 0,95, индекс = 2,85. Убедиться, что цвет столбца на гистограмме изменился на красный (риск >2).
11. Нажать кнопку «Выйти» в навигационной панели. Убедиться, что произошло перенаправление на страницу /login/.
12. В адресной строке ввести несуществующий URL. Убедиться, что отображается стандартная страница с кодом 404 (Not Found).
