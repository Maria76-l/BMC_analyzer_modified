До модификации приложение (информационный сервис 2000‑х) и контейнер безопасности (BMC_analyzer) работали независимо по протоколу HTTP; контейнер разворачивался на Replit без настроек безопасности (DEBUG=True, отсутствие SECURE_SSL_REDIRECT); приложение работало на устаревшей ВМ Linux, которая не функционирует.
После модификации контейнер становится единой HTTPS‑входной точкой. Все входящие HTTP‑запросы автоматически перенаправляются (301) на HTTPS. В контейнере включены: SECURE_SSL_REDIRECT, CSRF_COOKIE_SECURE, SESSION_COOKIE_SECURE, SECURE_HSTS_SECONDS и добавлен middleware для установки заголовков безопасности (HSTS, CSP, X‑Frame‑Options). Восстановленное приложение размещено внутри той же сетевой среды (Replit) и взаимодействует с контейнером по HTTP на локальном хосте (безопасно, так как трафик не выходит во внешнюю сеть).

2.3. Интерфейсы
Пользовательский веб интерфейс: ранее доступ по http://... (браузер отмечал «не защищено»), теперь автоматический редирект на https://... с отображением замка.
API контейнера: ранее все эндпоинты были доступны по HTTP, куки sessionid и csrftoken не имели флага Secure. После модификации все API эндпоинты доступны только по HTTPS, куки помечены Secure и HttpOnly, добавлен заголовок Strict-Transport-Security.
Взаимодействие внутреннего интерфейса контейнера и приложения ранее шло по HTTP между разными ВМ, теперь контейнер вызывает восстановленное приложение по HTTP на localhost (внутри одной платформы Replit), что исключает внешний перехват.
В интерфейс мониторинга добавлен эндпоинт /api/security-status/, возвращающий состояние настроек безопасности (например, {"ssl_redirect": true, "hsts_active": true, "secure_cookies": true}).
